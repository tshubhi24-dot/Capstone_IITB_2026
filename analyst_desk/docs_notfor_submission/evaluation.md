## Reading these results

- This is the **development** set (20 cases): it was used while building, so it shows what works, not how well the system generalises. The held-out set (40+, written by role 5) is the real test; run it three times and report the spread (evaluation protocol).
- Success counts what code can check: the right figures, Item 1A citations for both years, correct refusals. Explanation quality is for the calibrated judge (scripts/run.py calibrate).
- 'Numbers verified' is the share of numbers in the output that code can trace to XBRL or a cited passage. C0 writes free text, so most of its numbers cannot be traced even when correct.

## Role 6 accuracy accounting note

The older row "Numbers verified (mean %)" averages the verifier's per-case percentages,
including cases with `0/0` numbers recorded as 100%. It is **not** the overall fraction of
verified numbers. The separate reproducible audit in
[`role6_development_evidence.md`](role6_development_evidence.md) finds pooled dev shares of
**3.7% (C0, 2/54), 92.8% (C1, 77/83), and 71.5% (C2, 143/200)**. Both agent configurations
are below the **98% monitoring alert threshold** in this saved development snapshot. The
figures do not represent held-out performance or any new live experiment.
